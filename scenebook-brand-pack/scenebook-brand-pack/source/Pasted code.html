Design principle: keep the shell restrained, let generated work feel tactile, and make agent decisions visible enough to trust.

Brand foundation

Premium creator tooling, not enterprise cosplay.

The reference design system uses monumental type, restrained color, dark console surfaces, pill CTAs, and whitespace as a trust signal. SceneBook keeps the restraint but shifts the emotional center to creator throughput: a product that feels like a planning desk, production assistant, asset library, and editing handoff system in one.

Personality

Sharp, creative, practical, fast, calm under pressure. It should feel like a senior creative producer who can also operate the workspace.

Product promise

One project per reel. One agent that remembers the context. One path from idea → script → assets → edit → publish → learn.

Design stance

Dark-first and focused. White surfaces are reserved for review, documents, exports, and “final answer” clarity — not the main workspace.

Logo system

The SceneBook mark combines frame, script, play, and memory.

The logo should work as a dock icon, favicon, navbar mark, splash screen emblem, and creator-facing watermark. It must remain recognizable at 24px while feeling premium at 160px.

Gradient rule

Gradients appear inside media cards, thumbnails, generated asset previews, and hero posters. They should not become generic button or full-page backgrounds.

Border rule

Most containment uses 1px translucent lines. Shadows are rare and reserved for floating chat island, patch review, and modal drawers.

Focus rule

Keyboard focus uses Runtime Blue rings. Do not rely on color alone; pair with borders, labels, and state text.

Typography

Huge claims, quiet UI, readable production details.

The type system borrows the reference file’s tight display logic and restrained UI copy. The difference: SceneBook adds more mono labels for agent timeline, model routing, versioning, patch status, and asset provenance.

UX architecture

From tab maze to project cockpit.

The old workspace tab model splits assets, script, generation, tasks, editor, and analytics too early. The revamped IA makes the project overview a hub, the agent island the creation surface, the timeline the receipt trail, and patch review the trust layer.

Move

Script, shot list, prompts, assets, tasks, and packages become workflow-aware chat artifacts, not isolated tabs.

Elevate

Any large workspace mutation appears as a planned patch with diff, risk level, affected entities, and explicit apply action.

Runtime events must become visible product objects.

Component rules

Build fewer components, make them state-rich.

The app should not become a wall of cards. Open space, thin rules, and carefully named states will make the agent feel calmer and more credible.

App shell

Left compact rail, center workspace, right contextual drawer. Keep navigation quiet; creation should dominate.

Chat island

Centered on empty projects, then docks into the workspace once conversation begins. Composer supports /commands and model accordion.

Artifact cards

Workflow outputs are previewable, versioned, and selectable. Every generated object has provenance and next actions.

Patch review

Use white or high-contrast panels for diff readability. Risk labels, affected objects, and before/after copy are mandatory.

Asset drawer

Folders by scene/beat. Cards show type, model, prompt, status, and import state. Generated media gets thumbnail-first treatment.

Analytics

Keep analytics as the learning loop, not the main workspace. Use restrained charts, insight cards, and next experiment prompts.

Implementation handoff

Codex-ready UI revamp brief.

Use this as the implementation source of truth for the SceneBook UI revamp. The goal is to make agent/runtime outputs first-class UI objects while applying the new brand system.

prompt-for-coding-agent.md
You are implementing the SceneBook UI revamp across the current SceneBook app and agent runtime.

Primary objective:
Turn SceneBook from a tab-heavy creator workspace into a dark-first AI production workspace for short-form video creation. The agent chat must feel like the primary creation surface, while workflow packages, planned ProjectPatch outputs, timeline receipts, and asset/editor handoff become first-class UI objects.

Brand direction:
- Dark-first product shell: #07080B background, #141821 panels, #FFFDF8 document/review surfaces.
- Accent system: #FF6847 creative/cue coral, #69A7FF runtime/system blue, #B8FF6A applied/success, #A78BFA model selection.
- Typography: large tight display headings; restrained body copy; mono uppercase labels for runtime state.
- Use thin borders, rounded media/product cards, minimal shadows, pill controls, and generous whitespace.
- Avoid generic SaaS gradients, heavy shadows, childish rounded cards, and corporate dashboard clutter.

Information architecture:
1. Keep /projects/[id] as the overview hub.
2. Move script, shot list, generation, tasks, and package creation into the Agent workspace/chat island.
3. Keep Analytics as a separate learning-loop surface.
4. Asset drawer/folders should be accessible from the agent workspace and editor bridge.
5. Editor should receive selected scripts, shot tasks, generated assets, and handoff metadata.

Core screens to implement or refactor:
- Project Overview Hub: status, ProjectMind summary, selected direction, current stage, recent outputs, next recommended action.
- Agent Workspace: centered chat island, mode switcher, slash-command composer, model accordion, timeline rail, contextual drawer.
- Production Package Card: typed workflow output renderer with tabs/sections for script, shots, asset prompts, publish notes, editor handoff.
- Planned Patch Review: diff tree, affected objects, risk labels, inspect JSON, apply/edit/reject/version actions.
- Asset Drawer: scene/beat folders, generated thumbnails, prompt provenance, import-to-editor action.
- Editor Bridge: imports selected package parts and preserves provenance.

Runtime event renderers required:
- assistant_message → chat bubble with mode label and optional memory references.
- workflow_package → production package artifact card.
- project_patch_planned → patch review panel, not a generic tool card.
- creative_workflow_needs_input → missing-input card, not approval UI.
- tool_call/tool_result → collapsible receipt rows in timeline.
- asset_generated → asset card with provenance and scene link.
- error/recovery → recovery card with failed step and retry options.

Acceptance criteria:
- No workflow/package/patch output is rendered as a generic raw tool card.
- Large ProjectPatch outputs are never silently applied; they appear as planned patches with explicit Apply action.
- Timeline hydration persists enough state to reload workflow cards and patch review after refresh.
- UI clearly distinguishes needs_input, approval_required, patch_planned, patch_applied, and error states.
- ProjectMind facts/decisions are visible and editable from the agent workspace.
- The design is responsive: desktop 3-pane cockpit; tablet 2-pane; mobile single-column with drawers.
- Add tests for event-to-component mapping and patch review state transitions.

Suggested implementation phases:
Phase A: Add design tokens and app-shell primitives.
Phase B: Build typed runtime event renderer registry.
Phase C: Implement ProductionPackageCard and WorkflowTimeline.
Phase D: Implement PlannedPatchReview with apply/edit/reject states.
Phase E: Implement AssetDrawer and EditorBridge handoff.
Phase F: Polish responsive behavior, empty states, animations, a11y, and tests.

At the end of each phase: run lint/typecheck/tests and create a clear commit.
Do / Don’t

Guardrails for the revamp.

Use these to keep the implementation from drifting into either “enterprise AI dashboard” or “toy creator app.”

Do

Make the agent’s outputs inspectable. Show memory, decisions, receipts, patches, and provenance. Use dark surfaces for creation and white surfaces for final review.

Don’t

Do not scatter creation across disconnected tabs. Do not hide workspace mutations behind tool cards. Do not overuse gradients, glassmorphism, or vague AI sparkle.
